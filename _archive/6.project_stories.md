# Epic: SmartFastPay Ecuador USD Payin HPP
**Goal**: Integrate SmartFastPay as a payment provider for Bank Transfer Payins in Ecuador (USD) using the Hosted Payment Page (HPP) flow.

## Story 1: Authorization
### Description
As a System, I want to authenticate with the SmartFastPay API using Client Credentials so that I can perform secure transactions.

### Technical Specifications
*   **Method**: `POST /oauth2/token`
*   **Headers**: 
    *   `Authorization: Basic base64(client_id:client_secret)`
    *   `Content-Type: application/x-www-form-urlencoded`
*   **Body**: `grant_type=client_credentials`
*   **Response**: `{ "access_token": "...", "token_type": "Bearer", "expires_in": 3600 }`

### Acceptance Criteria

**Scenario: Successful Token Generation**
*   **Given** Valid `client_id` and `client_secret`
*   **When** I send a POST request to `/oauth2/token` with `grant_type=client_credentials`
*   **Then** I receive a 200 OK response
*   **And** The response contains a valid `access_token`
*   **And** The `token_type` is `Bearer`

**Scenario: Invalid Credentials**
*   **Given** Invalid `client_id` or `client_secret`
*   **When** I send a POST request to `/oauth2/token`
*   **Then** I receive a 401 Unauthorized response

## Story 2: PayIn Transaction Creation (HPP)
### Description
As a Merchant, I want to create a payment link for a user so that they can complete a Bank Transfer payment in Ecuador.

### Technical Specifications
*   **Method**: `POST /v2/transaction/checkout`
*   **Headers**: `Authorization: Bearer <access_token>`
*   **Body**:
    ```json
    {
      "customer": {
        "name": "User Name",
        "email": "user@email.com",
        "document": { "number": "1234567890", "type": "CI" }
      },
      "transaction": { "id": "unique_id", "currency": "USD", "amount": 10.00 },
      "country": "ECU",
      "payment_method": ["bank_transfer"],
      "notification_url": "https://callback.url"
    }
    ```
*   **Response**: Nested JSON containing `payment_url`.

### Acceptance Criteria

**Scenario: Successful Payment Link Creation**
*   **Given** A valid access token
*   **And** A transaction amount of 10.00 USD
*   **And** Valid customer data (Name, Email, Document CI)
*   **When** I send a POST request to `/v2/transaction/checkout`
*   **Then** I receive a 200 OK response
*   **And** The response contains a valid `payment_url` redirecting to the checkout page

**Scenario: Invalid Country**
*   **Given** A transaction request with `country: "BRA"` (Outside Scope)
*   **When** I send a POST request to `/v2/transaction/checkout`
*   **Then** I receive a 400 Bad Request or 422 Unprocessable Entity response

**Scenario: Missing Document**
*   **Given** A transaction request missing `customer.document`
*   **When** I send a POST request to `/v2/transaction/checkout`
*   **Then** I receive a 400 Bad Request response indicating missing required fields

## Story 3: Webhook Handling
### Description
As a System, I want to receive and process asynchronous notifications from SmartFastPay so that I can update the transaction status in real-time.

### Technical Specifications
*   **Endpoint**: `POST /api/webhooks` (Internal)
*   **Expected Payload**: JSON object containing `transaction.id`, `status` (`COMPLETED`, `DECLINED`), and `payment_date`.
*   **Mapping**:
    *   `COMPLETED` / `PAID` -> `1 SUCCESS`
    *   `DECLINED` / `REJECTED` / `EXPIRED` -> `2 FAILED`

### Acceptance Criteria

**Scenario: Successful Payment Notification**
*   **Given** A pending transaction exists in the system
*   **When** I receive a webhook with status `COMPLETED`
*   **Then** The system updates the transaction status to `SUCCESS`
*   **And** I respond with 200 OK

**Scenario: Failed Payment Notification**
*   **Given** A pending transaction exists in the system
*   **When** I receive a webhook with status `DECLINED`
*   **Then** The system updates the transaction status to `FAILED`
*   **And** I respond with 200 OK

## Story 4: Transaction Status Check
### Description
As a System, I want to manually check the status of a transaction so that I can reconcile data if webhooks fail.

### Technical Specifications
*   **Method**: `GET /v2/transaction/{transaction_id}`
*   **Headers**: `Authorization: Bearer <access_token>`
*   **Response**: JSON object with current status.

### Acceptance Criteria

**Scenario: Check Pending Status**
*   **Given** A valid transaction ID that has not been paid
*   **When** I send a GET request to `/v2/transaction/{id}`
*   **Then** I receive a 200 OK response
*   **And** The status is `PENDING` (or provider equivalent)

**Scenario: Check Completed Status**
*   **Given** A valid transaction ID that has been paid
*   **When** I send a GET request to `/v2/transaction/{id}`
*   **Then** I receive a 200 OK response
*   **And** The status is `COMPLETED`
