# Project Stories

## Story 1: Authorization

### Description
Implement authentication mechanism for SmartFastPay token generation.

### Method
OAuth 2.0 Client Credentials with Basic Authentication header.

### Implementation Details
**Endpoint**: `POST https://sandbox.smartfastpay.com/oauth2/token`

**Request Headers**:
```http
Authorization: Basic <base64(client_id:client_secret)>
Content-Type: application/json
Accept: application/json
```

**Request Body**:
```json
{
  "grant_type": "client_credentials"
}
```

**Response**:
```json
{
  "access_token": "eyJhbGc...",
  "token_type": "Bearer",
  "expires_in": 3600
}
```

**Token Usage**:
All subsequent requests must include:
```http
Authorization: Bearer {access_token}
```

### Acceptance Criteria
- [ ] Token generation successful (200 OK)
- [ ] Token used in subsequent requests as Bearer token
- [ ] Error handling for `401 Unauthorized` (INVALID_CLIENT)

## Story 2: Create Transaction Request

### Description
Create a payment transaction using the SmartFastPay Checkout Experience (HPP) flow for Ecuador bank transfers.

### Endpoint
`POST https://sandbox.smartfastpay.com/v2/payin`

### Field Mapping

| BetterBro Field | Provider Field | Transformation | Example |
|-----------------|----------------|----------------|---------|
| `amount` | `transaction.amount` | None (Decimal) | `10.00` |
| `currency` | `transaction.currency` | ISO 4217 | `USD` |
| `external_id` | `transaction.id` | None | `order_12345` |
| `customer.id` | `customer.id` | None | `cust_987` |
| `customer.full_name` | `customer.name` | None | `John Doe` |
| `customer.email` | `customer.email` | None | `user@example.com` |
| `customer.document` | `customer.document.number`| None | `1712345678` |
| `customer.document_type`| `customer.document.type`| None | `CI` |
| `callback_url` | `notification_url` | None | `https://api.betterbro.com/webhook` |
| `N/A` | `country` | Constant | `ECU` |
| `N/A` | `payment_method`| Constant | `bank_transfer` |

### Request Example
```json
{
  "customer": {
    "id": "cust_987",
    "name": "John Doe",
    "email": "user@example.com",
    "document": {
      "number": "1712345678",
      "type": "CI"
    }
  },
  "transaction": {
    "id": "order_12345",
    "currency": "USD",
    "amount": 10.00
  },
  "country": "ECU",
  "payment_method": "bank_transfer",
  "notification_url": "https://api.betterbro.com/webhook/order_12345"
}
```

### Response Example (Success)
```json
{
  "transaction_id": "SFP-67890",
  "status": "pending",
  "payment_url": "https://sandbox.smartfastpay.com/pay/abc123"
}
```

### Response Example (Error)
```json
{
  "error": "INVALID_AUTH_CODE",
  "message": "The provided authorization code is invalid or expired."
}
```

### Acceptance Criteria
- [ ] All mandatory fields (`customer.name`, `customer.document.number`, `transaction.amount`, etc.) mapped correctly.
- [ ] Transaction created successfully with `201 Created`.
- [ ] `payment_url` returned to redirect the user to HPP.
- [ ] Error handling for field validation implemented.

## Story 3: Create Transaction Response Parsing

### Description
Parse the SmartFastPay response and extract the redirect URL and internal transaction ID.

### Success Response Fields
| Field | Type | Purpose |
|-------|------|---------|
| `transaction_id` | string | SmartFastPay's transaction identifier |
| `status` | string | Current transaction status (e.g., `pending`) |
| `payment_url` | string | URL to redirect customer to the payment page |

### Error Response Fields
| Field | Type | Purpose |
|-------|------|---------|
| `error` | string | Internal error code |
| `message` | string | Human-readable explanation |

### Status Codes
| HTTP Code | Meaning | Action |
|-----------|---------|--------|
| 201 | Created | Success, redirect to `payment_url` |
| 400 | Bad Request | Log validation error |
| 401 | Unauthorized | Refresh access token and retry |
| 500 | Server Error | Log error, notify system admin |

## Story 4: Callback (Webhook)

### Description
Handle asynchronous status updates from SmartFastPay via POST notifications.

### Webhook Endpoint
`POST https://api.betterbro.com/webhook/{orderId}`

### Webhook Payload Example
```json
{
  "transaction_id": "SFP-67890",
  "status": "paid",
  "amount": 10.00,
  "currency": "USD",
  "id": "order_12345",
  "signature": "..."
}
```

### Validation Logic
1. **Signature Verification**: Verify the HMAC-SHA256 signature using the shared secret.
2. **Idempotency**: Ensure the transaction is not processed more than once by checking `transaction_id`.

### Response
Always return `200 OK` or `204 No Content` to acknowledge receipt.

### Acceptance Criteria
- [ ] Webhook signature validated (standard HMAC verification).
- [ ] Internal transaction status updated based on mapping.
- [ ] Idempotency handled using provider `transaction_id`.

## Story 6: Final Statuses Mapping

### Description
Map SmartFastPay statuses to internal 4bill/BetterBro statuses.
