**Integration**: SmartFastPay Ecuador USD Payin HPP

## Story 1: Authorization

### Description
Implement authentication mechanism for SmartFastPay API access using OAuth 2.0 Client Credentials flow.

### Method
OAuth 2.0 Client Credentials (Basic Auth)

### Implementation Details
**Endpoint**: `POST https://sandbox.smartfastpay.com/oauth2/token`

**Request Headers**:
```http
Authorization: Basic <base64(client_id:client_secret)>
Content-Type: application/json
Accept: application/json
```

**Response**:
```json
{
  "access_token": "eyJhbGc...",
  "token_type": "Bearer",
  "expires_in": 3600
}
```

**Token Usage**:
All subsequent requests must include:
```http
Authorization: Bearer {access_token}
```

### Acceptance Criteria
- [x] Token generation successful (Verified in Step 2)
- [x] Token used in subsequent requests (Verified in Step 4)
- [ ] Token refresh logic implemented

## Story 2: Create Transaction Request

### Description
Create payment transaction via the Checkout API and receive a hosted payment page (HPP) URL.

### Endpoint
`POST https://sandbox.smartfastpay.com/v2/transaction/checkout`

### Field Mapping

| BetterBro Field | Provider Field | Transformation | Example |
|-----------------|----------------|----------------|---------|
| `customer.id` | `customer.id` | String | `cust-123` |
| `customer.full_name` | `customer.name` | String | `John Doe` |
| `customer.email` | `customer.email` | String | `john@example.com` |
| `customer.document` | `customer.document.number` | String | `1712345678` |
| `customer.document_type` | `customer.document.type` | Enum (CI, RUC, PA) | `CI` |
| `external_id` | `transaction.id` | String | `order-789` |
| `amount` | `transaction.amount` | Decimal | `25.00` |
| `currency` | `transaction.currency`| ISO 4217 | `USD` |
| `country` | `country` | ISO 3166-1 alpha-3| `ECU` |
| `callback_url` | `notification_url` | String (URL) | `https://api.betterbro.com/webhook` |
| `return_url` | `redirect_url` | String (URL) | `https://example.com/return` |

### Request Example
```json
{
  "customer": {
    "id": "cust-ecu-101",
    "name": "Ecuador Verifier",
    "email": "verifier@example.com",
    "document": {
      "number": "1712345678",
      "type": "CI"
    }
  },
  "transaction": {
    "id": "test-trans-114095",
    "currency": "USD",
    "amount": 25.00
  },
  "country": "ECU",
  "payment_method": ["bank_transfer"],
  "notification_url": "https://api.betterbro.com/webhook/order-789",
  "redirect_url": "https://example.com/success"
}
```

### Response Example (Success)
```json
{
  "requestId": "27778fbec1260a9ef9d83ca126a308bd/18388016389273639818",
  "timestamp": "2026-01-30T06:46:46-03:00",
  "data": {
    "url": "https://sandbox-checkout.smartfastpay.com/v1/321e754f-c436-49c0-aeac-93bd2b711819/...",
    "transaction_id": "321e754f-c436-49c0-aeac-93bd2b711819"
  }
}
```

### Response Example (Error)
```json
{
  "moreInformation": [
    {
      "code": "INVALID_REQUEST",
      "detail": "The transaction.id field is required."
    }
  ]
}
```

### Acceptance Criteria
- [x] All required fields mapped correctly (Verified in Step 2)
- [x] Transaction created successfully (Verified in Step 4)
- [x] Payment URL returned (Verified in Step 4)
- [ ] Error handling for invalid document numbers (CI checksum) implemented

## Story 3: Create Transaction Response Parsing

### Description
Parse provider response and extract the HPP URL and provider transaction ID.

### Success Response Fields
| Field | Type | Purpose |
|-------|------|---------|
| `data.transaction_id` | string | Provider's transaction identifier |
| `data.url` | string | Hosted Payment Page (HPP) URL |

### Error Response Fields
| Field | Type | Purpose |
|-------|------|---------|
| `moreInformation[0].code` | string | Error code (e.g., INVALID_REQUEST) |
| `moreInformation[0].detail` | string | Human-readable error message |

### Status Codes
| HTTP Code | Meaning | Action |
|-----------|---------|--------|
| 200 | Success | Redirect user to `data.url` |
| 400 | Bad Request | Log error, return validation error to user |
| 401 | Unauthorized | Refresh token, retry once |
| 500 | Server Error | Retry with exponential backoff |

## Story 4: Callback (Webhook)

### Description
Handle asynchronous notifications from SmartFastPay about transaction status updates.

### Webhook Endpoint
Provider will POST to: `notification_url` provided in the create request.

### Webhook Payload Example
```json
{
  "transaction_id": "321e754f-c436-49c0-aeac-93bd2b711819",
  "status": "paid",
  "amount": 25.00,
  "currency": "USD",
  "timestamp": "2026-01-30T07:10:00-03:00"
}
```

### Validation Logic
1. **Signature Verification**: Check for signature header (logic typically involves a shared secret).
2. **Idempotency**: Check if `transaction_id` was already processed.

### Response
Return `200 OK` to acknowledge receipt.

### Acceptance Criteria
- [ ] Webhook signature validated
- [ ] Transaction status updated based on `status` field
- [ ] Idempotency ensured
- [x] Webhook polling mechanism verified (Step 4)

## Story 5: Check Status

### Description
Manually poll transaction status as a fallback for webhooks.

### Endpoint
`GET https://sandbox.smartfastpay.com/v2/transaction/{transaction_id}`

### Response Example
```json
{
  "data": {
    "transaction_id": "321e754f-c436-49c0-aeac-93bd2b711819",
    "status": "paid",
    "amount": 25.00,
    "currency": "USD"
  }
}
```

### Polling Strategy
- Poll every 30 seconds for the first 5 minutes.
- Then every 2 minutes for the next 25 minutes.
- Timeout after 30 minutes.
