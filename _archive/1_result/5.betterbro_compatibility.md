## 1. Rulebook Identification
- **Selected Rule**: Acquiring Form (HPP / Redirect)
- **Service Instance**: Ecuador Bank Transfer Payin HPP
- **Provider Service URL**: [SmartFastPay Checkout Overview](https://docs.smartfastpay.com/thesmartway/checkout-experience/overview)

- **Confidence**: High
- **Rationale**: The integration utilizes the SmartFastPay Checkout (HPP) model for bank transfers in Ecuador, which perfectly aligns with the BetterBro "Acquiring Form" rule and the specific Ecuador Bank Transfer service instance.

## 2. Field Mapping Feasibility
| Provider Field | BetterBro Standard Field | Notes |
| :--- | :--- | :--- |
| `transaction.amount` | `amount` | SFP: Decimal (e.g. 10.00). BB: Integer (1000). Conversion: `amount * 100`. |
| `transaction.currency` | `amount_currency` | Direct match (`USD`). |
| `transaction.id` | `external_transaction_id` | Unique Merchant Identifier. |
| `country` | `fields.country` | SFP: `ECU` (Alpha-3). BB: `EC` (Alpha-2). Conversion required. |
| `customer.name` | `fields.first_name` / `fields.last_name` | SFP: Full Name. BB: Split fields. Recommended to split by space or map whole to `first_name`. |
| `customer.id` | `fields.tax_id` | Document Number. |
| `customer.id_type` | `fields.tax_id_type` | SFP: `CC` (Cedula Ciudadania). BB: `CI` (National ID). Mapping: `CC` -> `CI`. |
| `customer.email` | `fields.email` | Mapped directly. |
| `notification_url` | `point.callback_url` | Webhook URL for status updates. |
| `redirect_url` | `point.return_url` | Return URL after payment completion/cancellation. |

**Missing Fields**:
- None identified. All mandatory provider fields have a clear home in the BetterBro schema.

## 3. Status Mapping (The "Rosetta Stone")
| Provider Status | 4bill Internal Code | Logic/Rule |
| :--- | :--- | :--- |
| `open` | `10 PENDING` | Transaction created, awaiting customer action on HPP. |
| `paid` / `success` | `1 SUCCESS` | Final success status. |
| `failed` / `denied` | `2 FAILED` | Final failure status. |
| `cancelled` | `3 CANCELLED` | User or operator cancellation. |
| `expired` | `5 EXPIRED` | HPP link or transaction timeout. |

**Ambiguous Statuses**:
- None. SmartFastPay statuses are standard and map cleanly to the 4bill internal lifecycle.

## 4. Automation & Logic
- **Architecture Type**: HPP / Redirect
- **Deterministic**: Yes. The flow follows a strict sequence: Create -> Redirect -> Callback.
- **Webhooks**: Standard POST notifications (as verified in Step 4). Security verification via signature is expected (as per BB standards).

## 5. Blocking Issues & Risks
- [RISK] **Document Type Convention**: Ensure the integration explicitly maps `CC` (SFP) to `CI` (BB) to avoid confusion, as `CC` is the specific requirement for Ecuador in SFP.
- [RISK] **Country Code Conversion**: The integration must handle the conversion from `ECU` (Alpha-3) to `EC` (Alpha-2) if data is sourced from BetterBro's internal systems in Alpha-2.
