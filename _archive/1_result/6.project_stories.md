# Epic: SmartFastPay Ecuador USD Payin HPP
**Goal**: Integrate SmartFastPay as a payment provider for Ecuador (USD) using the Hosted Payment Page (HPP) model for Bank Transfers.

## Story 1: Authorization
### Description
As a System, I want to authenticate with the SmartFastPay API using OAuth 2.0 Client Credentials flow to obtain a secure access token for transaction operations.

### Technical Specifications
*   **Endpoint**: `POST https://api.smartfastpay.com/oauth2/token`
*   **Headers**: 
    *   `Content-Type: application/x-www-form-urlencoded`
    *   `Authorization: Basic <base64(client_id:client_secret)>`
*   **Body Params**:
    *   `grant_type`: `client_credentials`
*   **Token Expiry**: 3600 seconds (1 hour).

### Acceptance Criteria (Gherkin)

**Scenario: Successful Token Generation**
*   **Given** Valid `client_id` and `client_secret`
*   **When** I request an access token from the oauth2/token endpoint
*   **Then** I receive a 200 OK response
*   **And** The response contains an `access_token`
*   **And** The `expires_in` field is `3600`

**Scenario: Authentication Failed**
*   **Given** Invalid API credentials
*   **When** I request an access token
*   **Then** I receive a 401 Unauthorized response

## Story 2: Transaction Initiation (Payin HPP)
### Description
As a Merchant, I want to create a payment checkout link for a customer in Ecuador so they can complete a Bank Transfer in USD.

### Technical Specifications
*   **Endpoint**: `POST https://api.smartfastpay.com/v2/transaction/checkout`
*   **Headers**: 
    *   `Authorization: Bearer <access_token>`
    *   `Content-Type: application/json`
*   **Request Body (JSON)**:
    ```json
    {
      "transaction": {
        "id": "merchant_order_id_123",
        "amount": 10.50,
        "currency": "USD"
      },
      "country": "ECU",
      "customer": {
        "name": "John Doe",
        "id": "1701234567",
        "id_type": "CC",
        "email": "john@example.com"
      },
      "notification_url": "https://callback.url/webhook",
      "redirect_url": "https://merchant.site/return"
    }
    ```
*   **Ecuador Specifics**: `country` must be `ECU`, `id_type` must be `CC` (Cedula Ciudadania).

### Acceptance Criteria (Gherkin)

**Scenario: Successful HPP URL Generation**
*   **Given** Valid customer data for Ecuador and USD currency
*   **And** A valid Bearer token
*   **When** I send a checkout request
*   **Then** I receive a 200 OK response
*   **And** The response contains a `data.url` (Redirect URL)
*   **And** The response contains a `data.transaction_id` (Provider ID)

**Scenario: Unsupported Country**
*   **Given** A country code other than `ECU` (e.g., `PER`)
*   **When** I send a checkout request
*   **Then** I receive a 400 Bad Request
*   **And** The error message states "It is not possible to have transactions in this country"

## Story 3: Webhook Handling
### Description
As a System, I want to process asynchronous status notifications from SmartFastPay to update the internal transaction state.

### Technical Specifications
*   **Method**: `POST` (sent by provider to `notification_url`)
*   **Payload Format**: JSON
*   **Status Mapping**:
    *   `open` -> `PENDING`
    *   `paid` / `success` -> `SUCCESS`
    *   `failed` / `denied` -> `FAILED`
    *   `cancelled` -> `CANCELLED`
    *   `expired` -> `EXPIRED`

### Acceptance Criteria (Gherkin)

**Scenario: Successful Payment Notification**
*   **Given** An active pending transaction
*   **When** SmartFastPay sends a POST notification with status `paid` or `success`
*   **Then** The system updates the transaction state to `SUCCESS`

**Scenario: Transaction Expired Notification**
*   **Given** A pending transaction
*   **When** SmartFastPay sends a notification with status `expired`
*   **Then** The system updates the transaction state to `EXPIRED`

## Story 4: Transaction Status Polling
### Description
As a System, I want to manually query the status of a transaction if a webhook is delayed or missing.

### Technical Specifications
*   **Endpoint**: `GET https://api.smartfastpay.com/v2/transaction/{transaction_id}` (or merchant order ID based on provider pattern)
*   **Headers**: `Authorization: Bearer <access_token>`

### Acceptance Criteria (Gherkin)

**Scenario: Fetch Current Transaction Status**
*   **Given** A valid provider `transaction_id`
*   **When** I request the transaction status
*   **Then** I receive a 200 OK response
*   **And** The response contains the current `status` (e.g., `paid`)

---

## Story 5: Error Handling & Validation
### Description
As a Merchant, I want to receive clear validation errors for incorrect request payloads to handle edge cases before redirecting the user.

### Technical Specifications
*   **Validation Rules**:
    *   `notification_url`: Mandatory.
    *   `transaction.amount`: Mandatory, decimal format.
    *   `customer.id_type`: Must be `CC` for Ecuador.

### Acceptance Criteria (Gherkin)

**Scenario: Missing Mandatory Webhook URL**
*   **Given** A checkout request missing the `notification_url` field
*   **When** The request is sent to the provider
*   **Then** I receive a 400 Bad Request
*   **And** The message includes "The notification url field is required"

**Scenario: Incorrect Document Type for Ecuador**
*   **Given** A checkout request with `country` as `ECU` but `id_type` as `PASSPORT`
*   **When** the request is processed by the provider
*   **Then** I receive a 400 Bad Request (as per gap analysis in `2.docs_analysis.md`)

## Workflow Suggestions
- **Configuration**: Standardize `ECU` and `CC` as constants for this integration.
- **Monitoring**: Log the `requestId` from every SFP response for easier debugging with the provider.
- **Resilience**: Implement a retry mechanism for token generation if the 401 response is received unexpectedly.
