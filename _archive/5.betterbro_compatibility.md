# BetterBro Compatibility Report

**Date**: 2026-02-03

## 1. Rulebook Identification
- **Selected Rule**: Acquiring Form
- **Service Instance**: Ecuador Bank Transfer Payin HPP
- **Provider Service URL**: [SmartFastPay Checkout API](https://docs.smartfastpay.com/thesmartway/checkout-experience/overview)
- **BetterBro Service URL**: [https://docs.betterbro.com/services/ecuador/bank_transfer/payin_hpp](https://docs.betterbro.com/services/ecuador/bank_transfer/payin_hpp)
- **Confidence**: High
- **Rationale**: The integration uses a strictly defined HPP flow where the user is redirected to a `payment_url`. The API requires standard customer and transaction data and returns a URL, fitting the "Acquiring Form" rule perfectly.

## 4. Automation & Logic
- **Architecture Type**: HPP (Redirect)
- **Deterministic**: Yes. The flow is: Auth -> Create Transaction -> Get Link -> User Pays -> Webhook.
- **Webhooks**: Standard JSON payload expected.

## 5. Blocking Issues & Risks
- **[RISK] Document Type Validation**: The sandbox was picky about `document.type` matching the number format (e.g., `CI` vs `CC`). Logic must ensure the correct type is sent for the given ID.
- **[RISK] Country Code**: Discrepancy found during testing between `ECU` and `EC`. Production documentation says `ECU` (ISO alpha-3), but some endpoints might accept/require alpha-2. We will standardize on the one that worked (`ECU` worked in final successful test).
