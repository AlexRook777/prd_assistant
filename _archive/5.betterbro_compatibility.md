# BetterBro Compatibility Report

**Date**: 2026-02-04

## 1. Rulebook Identification
- **Selected Rule**: Acquiring Form (HPP)
- **Service Instance**: Ecuador Bank Transfer Payin HPP
- **Provider Service URL**: [https://docs.smartfastpay.com/thesmartway/checkout-experience/overview](https://docs.smartfastpay.com/thesmartway/checkout-experience/overview)
- **BetterBro Service URL**: [https://docs.betterbro.com/services/ecuador/bank_transfer/payin_hpp](https://docs.betterbro.com/services/ecuador/bank_transfer/payin_hpp)
- **Confidence**: High
- **Rationale**: The provider offers a Hosted Payment Page (HPP) flow for Bank Transfers in Ecuador (USD), which perfectly aligns with the BetterBro "Bank Transfer Payin HPP" rule for the Ecuador region.

## 2. Field Mapping Feasibility
| Provider Field | BetterBro Standard Field | Notes |
| :--- | :--- | :--- |
| `customer.id` | `external_customer_id` | Direct match |
| `customer.name` | `fields.first_name` / `fields.last_name` | Split if possible, otherwise map to name fields |
| `customer.email` | `fields.email` | Direct match |
| `customer.tax_id_type` | `fields.tax_id_type` | Both support CI, RUC, PASS |
| `customer.tax_id` | `fields.tax_id` | Direct match |
| `transaction.id` | `external_transaction_id` | Direct match |
| `transaction.amount` | `amount` | **CRITICAL**: Conversion needed (Decimal to Int: *100) |
| `transaction.currency` | `amount_currency` | Direct match (USD) |
| `country` | `fields.country` | **Note**: Map ECU (alpha-3) to EC (alpha-2) |
| `notification_url` | `point.callback_url` | Direct match |
| `redirect_url` | `point.return_url` | Direct match |

**Missing Fields**:
- `fields.phone`: Mandatory for BetterBro. If not provided by merchant, BetterBro handles it on the payment page.
- `customer_ip_address`: Mandatory for BetterBro. Must be captured from the user/agent.

## 3. Status Mapping (The "Rosetta Stone")
| Provider Status | 4bill Internal Code | Logic/Rule |
| :--- | :--- | :--- |
| `paid` | `1 SUCCESS` | Payment confirmed by provider |
| `denied` | `2 FAILED` | Explicitly rejected or failed |
| `expired` | `2 FAILED` | Session timeout treated as failure |
| `pending` | `3 PENDING` | Awaiting customer action |

**Ambiguous Statuses**:
- None. The status set is simple and deterministic.

## 4. Automation & Logic
- **Architecture Type**: HPP (Redirect)
- **Deterministic**: Yes. The flow follows a predictable Redirect -> Callback pattern.
- **Webhooks**: Standard POST. Signature verification recommended.

## 5. Blocking Issues & Risks
- [RISK] **Amount Handling**: SmartFastPay uses decimals (10.00), whereas BetterBro requires integers (1000). Arithmetic errors must be avoided.
- [NOTE] **Document Validation**: Document format requirements (e.g., RUC must be 13 digits) must be strictly enforced on the frontend or normalized.

## 6. Recommendation
- [x] **GREEN LIGHT**: Fully compatible, proceed to implementation.
