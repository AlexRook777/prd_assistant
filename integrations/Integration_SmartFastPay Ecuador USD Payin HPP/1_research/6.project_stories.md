## Story 1: Authorization

### Description
Implement authentication mechanism for SmartFastPay API access using OAuth 2.0 Client Credentials grant.

### Method
OAuth 2.0 Client Credentials

### Implementation Details
**Endpoint**: `POST https://sandbox.smartfastpay.com/oauth2/token`

**Request Headers**:
```http
Authorization: Basic <base64(client_id:client_secret)>
Content-Type: application/json
Accept: application/json
```

**Request Body**:
```json
{
  "grant_type": "client_credentials"
}
```

**Response**:
```json
{
  "access_token": "eyJhbGc...",
  "token_type": "Bearer",
  "expires_in": 3600
}
```

**Token Usage**:
All subsequent requests must include:
```http
Authorization: Bearer {access_token}
```

### Acceptance Criteria
- [ ] Token generation successful (Basic Auth header used)
- [ ] Token used in subsequent requests as Bearer
- [ ] Token refresh logic implemented if 401 is received

## Story 2: Create Transaction Request (Payin HPP)

### Description
Create a payment transaction using the "Checkout Experience" (HPP) to receive a payment link or redirect URL.

### Endpoint
`POST https://sandbox.smartfastpay.com/v2/payin`

### Field Mapping

| BetterBro Field | Provider Field | Transformation | Example |
|-----------------|----------------|----------------|---------|
| `amount` | `transaction.amount` | None (Decimal) | `10.50` |
| `currency` | `transaction.currency` | ISO 4217 | `USD` |
| `external_id` | `transaction.id` | None | `order_12345` |
| `customer.id` | `customer.id` | None | `cust_987` |
| `customer.full_name`| `customer.name` | None | `John Doe` |
| `customer.email` | `customer.email` | None | `user@example.com` |
| `customer.document`| `customer.document.number`| None | `1712345678` |
| `customer.document_type`| `customer.document.type`| Map to provider types | `CI` |
| `country` | `country` | ISO Alpha-3 | `ECU` |
| `service_code` | `payment_method` | Map to `bank_transfer`| `bank_transfer`|
| `callback_url` | `notification_url` | None | `https://api.betterbro.com/webhook` |
| `return_url` | `redirect_url` | None | `https://example.com/success` |

### Request Example
```json
{
  "customer": {
    "id": "cust_987",
    "name": "John Doe",
    "email": "user@example.com",
    "document": {
      "number": "1712345678",
      "type": "CI"
    }
  },
  "transaction": {
    "id": "order_12345",
    "currency": "USD",
    "amount": 10.50
  },
  "country": "ECU",
  "payment_method": "bank_transfer",
  "notification_url": "https://api.betterbro.com/webhook/order_12345",
  "redirect_url": "https://example.com/return"
}
```

### Response Example (Success)
```json
{
  "transaction_id": "SFP_554433",
  "status": "pending",
  "payment_url": "https://checkout.smartfastpay.com/pay/abc123xd",
  "expires_at": "2026-01-30T15:00:00Z"
}
```

### Response Example (Error)
```json
{
  "error": "INVALID_CLIENT",
  "message": "Invalid client credentials provided"
}
```

### Acceptance Criteria
- [ ] All required fields mapped (customer info is included to simplify HPP flow)
- [ ] Transaction created successfully
- [ ] `payment_url` returned and usable for redirection
- [ ] Error handling for invalid fields (e.g., amount < 6 USD)

## Story 3: Create Transaction Response Parsing

### Description
Parse provider response and extract the `payment_url` and provider's `transaction_id`.

### Success Response Fields
| Field | Type | Purpose |
|-------|------|---------|
| `transaction_id` | string | SmartFastPay transaction identifier |
| `status` | string | Current status (e.g., `pending`) |
| `payment_url` | string | URL for customer redirection |
| `expires_at` | datetime | Expiration of the payment session |

### Error Response Fields
| Field | Type | Purpose |
|-------|------|---------|
| `error` | string | Machine-readable error code |
| `message` | string | Human-readable explanation |

### Status Codes
| HTTP Code | Meaning | Action |
|-----------|---------|--------|
| 201 | Created | Success, redirect user |
| 400 | Bad Request | Log error, return validation failure |
| 401 | Unauthorized | Refresh token, retry once |
| 403 | Forbidden | Check restricted IP or permissions |
| 500 | Server Error | Log and return technical error |

## Story 4: Callback (Webhook)

### Description
Handle asynchronous POST notifications from SmartFastPay regarding transaction status updates.

### Webhook Endpoint
Provider will POST to: `https://api.betterbro.com/webhook/{orderId}`

### Webhook Payload Example
```json
{
  "transaction_id": "SFP_554433",
  "status": "paid",
  "amount": 10.50,
  "currency": "USD",
  "timestamp": "2026-01-30T14:30:00Z",
  "signature": "hmac_signature_here"
}
```

### Validation Logic
1. **Signature Verification**:
   - Verify HMAC signature using the shared secret.
2. **Idempotency**:
   - Ensure transaction isn't already marked as `SUCCESS` or `FAILED` before processing.

### Response
Return `200 OK` to stop retries:
```json
{
  "status": "received"
}
```

### Acceptance Criteria
- [ ] Webhook signature validated
- [ ] Transaction status updated in database
- [ ] Idempotency handled (don't process `paid` twice)
- [ ] Appropriate response sent back to provider

## Story 5: Check Status (Polling)

### Description
Manually poll the transaction status via API as a fallback for missing webhooks.

### Endpoint
`GET https://sandbox.smartfastpay.com/v2/transaction/{id}`

### Response Example
```json
{
  "transaction_id": "SFP_554433",
  "status": "paid",
  "amount": 10.50,
  "created_at": "2026-01-30T14:00:00Z",
  "paid_at": "2026-01-30T14:15:00Z"
}
```

### Polling Strategy
- First 10 minutes: Every 1 minute.
- Next 50 minutes: Every 5 minutes.
- After 1 hour: Mark as expired if no update.

## Story 6: Final Statuses Mapping

### Description
Map SmartFastPay statuses to BetterBro internal statuses.

| Provider Status | Internal Status | Meaning |
|----------------|-----------------|---------|
| `paid` | `SUCCESS` | Payment completed |
| `pending` | `PENDING` | Awaiting action |
| `cancelled` | `FAILED` | User or provider cancelled |
| `refunded` | `REFUNDED` | Funds returned |
| `expired` | `FAILED` | Timeout reached |
