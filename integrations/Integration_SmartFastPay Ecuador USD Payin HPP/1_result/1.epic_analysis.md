# Epic Analysis

**Integration Name**: SmartFastPay Ecuador USD Payin HPP  
**Date**: 2026-02-02

## Summary
- **Payment Method**: Bank Transfer (Initially), all payment methods for Ecuador
- **Countries**: Ecuador
- **Currencies**: USD
- **Flow Type**: HPP (Redirect)
- **Transaction Types**: Payin

The integration is centered on the SmartFastPay provider for the Ecuador market using USD. The implementation uses the "Checkout Experience" (HPP) where user details are either pre-filled or entered on the provider's side.

## BetterBro Alignment (Draft)
- **Service Rule**: Acquiring Form / HPP
- **BetterBro Service URL**: [https://docs.betterbro.com/services/ecuador/bank_transfer/payin_hpp](https://docs.betterbro.com/services/ecuador/bank_transfer/payin_hpp)

## Clarified Points (User Feedback)
- **Integration Scope**: This specific integration folder covers **Ecuador only**. Peru (PEN) is handled separately or is out of scope for this task.
- **Tax ID Type (User Input)**: The initial request specified `CI` for Ecuador.
- **Tax ID Type (Technical Discovery)**: Active verification in Step 2 confirms that the API rejects `CI` with an error (`Document type CI not found`). Use **`CC`** (Cédula de Ciudadanía) for national IDs or **`RUC`** for business IDs.

## Requirements
- Support for Ecuador Bank Transfer in USD.
- Implementation via SmartFastPay Checkout Experience (HPP).
- Language support: Spanish and English.
- Limits for Ecuador:
  - Per transaction: Min 6 USD, Max 1,000 USD.
  - Per user: Max daily 1,200 USD, Max monthly 36,000 USD.
- Expected fields from merchants: `amount`, `name`, `tax_id_type` (`CC` / `RUC`), `tax_id`, `email`.
- Credentials and sandbox access are already available.

## Technical Constraints
- **Document Type Constraint**: The API strictly requires `CC` or `RUC` for Ecuador; `CI` is not supported despite the initial requirement.
- **Documentation Discrepancy**: The provider's documentation might be outdated. Specifically, `customer_fields` should NOT be sent in the create request, contrary to what some docs might suggest.
- **Flow Note**: If customer details are passed in the request, they will be pre-filled on the HPP; if not, the user will be prompted to enter them.
- **Integration Timeline**: High priority, with expectation of quick implementation for HPP.
