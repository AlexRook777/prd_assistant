# Contract Specification: SmartFastPay Ecuador

This document summarizes the machine-executable contract generated for the SmartFastPay Ecuador USD Bank Transfer Payin HPP integration.

## Scope & Metadata
- **Integration**: SmartFastPay Ecuador - USD - Bank Transfer Payin HPP
- **Rulebook**: Acquiring Form (HPP)
- **Region**: ECU
- **Currency**: USD
- **Environment**: Sandbox / Production

## Key Endpoints
1. **[POST] `/oauth2/token`**: Generates a Bearer token required for all subsequent calls.
2. **[POST] `/v2/transaction/checkout`**: Creates the HPP session and returns a `pay_url`.
3. **[GET] `/v2/transaction/{id}`**: Polls the current status of a transaction.

## BetterBro Alignment
The specification includes `x-betterbro-*` extensions to ensure seamless integration with internal systems:

### Field Mappings
| Category | Provider Field | BetterBro Standard | Note |
| :--- | :--- | :--- | :--- |
| Amount | `transaction.amount` | `amount` | Converted to integer cents (*100). |
| ID | `transaction.id` | `external_transaction_id` | Merchant side identifier. |
| Customer| `customer.id` | `external_customer_id` | Internal customer mapping. |
| Document| `customer.document.num`| `fields.tax_id` | Mandatory for Ecuador (Cedula/RUC). |

### Status Mappings
| Provider Status | Internal Code | Type |
| :--- | :--- | :--- |
| `open` | `10 PENDING` | Intermediate |
| `paid` | `1 SUCCESS` | Final |
| `cancelled`| `3 CANCELLED` | Final |
| `failed` | `2 FAILED` | Final |
| `expired` | `5 EXPIRED` | Final |

## Webhooks
- **Receiver**: Dynamic `notification_url` sent in checkout request.
- **Verification**: HMAC SHA-256 via `X-Signature` (Provider specific).
- **Mapping**: Payload fields are mapped to BetterBro standards via extensions.
