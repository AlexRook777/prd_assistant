# Documentation Analysis

**Provider**: SmartFastPay
**Documentation URL**: [https://docs.smartfastpay.com/thesmartway/checkout-experience/overview](https://docs.smartfastpay.com/thesmartway/checkout-experience/overview)
**Date**: 2026-02-12

## Clarified Points (User Feedback)
- **Scope**: Ecuador only (USD).
- **Flow**: HPP (Hosted Payment Page) via Checkout API.
- **Payment Method**: Bank Transfer (`bank_transfer`).
- **Payouts**: Out of scope.

## Authentication
### Method
OAuth 2.0 with Bearer Token.
### Token Generation
- **Endpoint**: `POST https://sandbox.smartfastpay.com/oauth2/token`
- **Required Headers**: `Content-Type: application/x-www-form-urlencoded`, `Authorization: Basic <base64(client_id:client_secret)>`
- **Required Credentials**: `client_id`, `client_secret` (Grant type: `client_credentials`)
- **Token Lifetime**: 3600 seconds (1 hour).

### Verification (MANDATORY)
Successfully verified. Obtained token using:
```bash
curl -X POST "https://sandbox.smartfastpay.com/oauth2/token" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     -u "CLIENT_ID:CLIENT_SECRET" \
     -d "grant_type=client_credentials"
```

## Transaction Initiation
### Create Transaction Endpoint
- **Endpoint**: `POST https://sandbox.smartfastpay.com/v2/transaction/checkout`
- **HTTP Method**: POST
- **Request Format**: application/json
- **Authentication**: Bearer Token in `Authorization` header

### Data Structure
#### Mandatory Fields
| Field | Type | Format | Description | Example |
|-------|------|--------|-------------|---------|
| `customer.id` | string | UUID/String | Unique customer identifier | "test-cust-127" |
| `customer.document.number` | string | 10 digits | ID document number (Cedula) | "2234583876" |
| `customer.document.type` | string | "CC", "RUC", "PA" | Document type code | "CC" |
| `transaction.id` | string | UUID/String | Internal order identifier | "order-ext-127" |
| `transaction.currency` | string | ISO 4217 | Currency code | "USD" |
| `transaction.amount` | number | Decimal(10,2) | Transaction amount | 10.00 |
| `country` | string | ISO 3166-1 (3) | Country code | "ECU" |
| `payment_method` | array[string] | Array | List of method codes | ["bank_transfer"] |
| `notification_url` | string | URL | Webhook callback URL | "https://..." |

#### Optional Fields
| Field | Type | Format | Description | Default |
|-------|------|--------|-------------|---------|
| `customer.name` | string | String | Customer full name | null |
| `customer.email` | string | Email | Customer email address | null |
| `branch` | string | String | Branch/Location identifier | null |
| `redirect_url` | string | URL | Success redirect URL | null |

### Expected Results
- **Success Status Code**: 200 OK
- **Response Structure**:
```json
{
  "requestId": "...",
  "timestamp": "2026-02-12T...",
  "data": {
    "url": "https://sandbox-checkout.smartfastpay.com/v1/...",
    "transaction_id": "335380ec-7e69-4b6f-bef3-163b09900757",
    "expires_at": "..."
  }
}
```
- **Transaction ID Format**: UUID format.
- **Transaction ID Location**: `data.transaction_id`.

## Payment URL Response
- **URL Location**: `data.url`
- **URL Format**: `https://sandbox-checkout.smartfastpay.com/v1/{id}/{hashed_method}/{payload}`
- **Redirect Behavior**: User is redirected to this URL to complete payment. Upon completion, they are redirected to `redirect_url`.

## Status Sets
### Complete Status List
| Status | Description | Type | Next Possible States |
|--------|-------------|------|---------------------|
| `open` | Transaction created, awaiting payment | Intermediate | paid, failed, expired |
| `paid` | Payment successful | Final | - |
| `failed` | Payment failed | Final | - |
| `expired` | Transaction session timed out | Final | - |

### Status Flow
```
open → paid (success)
open → failed (rejection)
open → expired (timeout)
```

## API Endpoints
### Check Status
- **Endpoint**: `GET https://sandbox.smartfastpay.com/v2/transaction/{id}` (Uses internal `id` or `transaction_id` depending on implementation, but sandbox verified `id` from `data.transaction_id`).
- **Authentication**: Bearer Token

### Webhook Callback
- **Format**: POST to `notification_url`.
- **Payload Structure**: Anticipated to contain `id`, `status`, and `transaction_id`.
- **Secret/Signature**: Managed via dashboard (to be verified in production).

## Negative Testing (Validation)
| Test Case | Variation | Expected | Actual Code | JSON Error |
|-----------|-----------|----------|-------------|------------|
| Missing Mandatory | Omit Name | 200 | 200 | (Accepted - Optional in HPP) |
| Negative Amount | amount: -5.00 | 400 | 400 | `{"code":"INVALID_REQUEST","detail":"The transaction.amount must be greater than 0"}` |
| Missing ID | Omit transaction.id | 400 | 400 | `{"code":"INVALID_REQUEST","detail":"The transaction.id is required"}` |
| Invalid Checksum | Bad CC number | 400 | 400 | `{"code":"INVALID_REQUEST","detail":"The value in field customer.document.number is invalid by type Cedula Ciudadania"}` |

## Gap Analysis (Discrepancies)
- Documentation inconsistently spells "Ecuador" as "Equador" in sub-pages.
- `customer.name` and `customer.email` are optional in the HPP flow despite being marked as "yes" in some overview tables.
- Country code `ECU` is strictly required for the `payment_method` to be accepted.

## Workflow Suggestions
1. **Dynamic ID Generation**: Ensure `transaction.id` is unique per request to avoid collision errors.
2. **ID Mapping**: Store both our `transaction_id` and the provider's `id` (returned in `data.transaction_id`) for status polling.
