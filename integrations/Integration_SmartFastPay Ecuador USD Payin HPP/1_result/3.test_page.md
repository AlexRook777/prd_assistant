## Usage Instructions

1.  **Authentication**:
    - Ensure `Client ID` and `Client Secret` are correct (pre-filled with sandbox credentials).
    - Click **Get Token**. The access token will appear in the field below.
2.  **Transaction Creation**:
    - Fill in the transaction details. `Transaction ID` is auto-generated.
    - `Amount` must be greater than 0.
    - `Doc Number` must be a valid 10-digit Cedula for Ecuador (default: `2234583876`).
    - Click **Create Transaction**.
3.  **Payment**:
    - A **Payment URL** will be displayed. Click it to open the Hosted Payment Page in a new tab.
    - Complete the payment flow on the provider's side.
4.  **Verification**:
    - Click **Check Status** to poll the API for the current transaction status.
    - Incoming webhooks will appear in the **Webhooks** section (auto-polls every 5 seconds).

## Features

- **3-Column Compact Layout**: Credentials | Transaction Form | Logs & Webhooks.
- **Proxy Toggle**: Routes requests through `http://localhost:8000/proxy` to avoid CORS issues from the browser.
- **Webhook Modes**:
    - **N8n Webhooks (Default)**: Uses a unique UUID for each session to test callbacks via our n8n infrastructure.
    - **Local Webhooks**: Routes callbacks to `http://localhost:8000/webhook`.
- **API Logs**: Detailed request/response logs with header and body inspection.
- **Persistent State**: Credentials and settings are saved in `sessionStorage`.

## Workflow Suggestions

1. **Automation Ready**: Use the unique IDs and known document values for automated browser testing.
2. **Error Debugging**: Use the API Logs to identify exact field validation errors from the provider.
3. **Webhook Verification**: Test both success and failure callbacks by controlling the flow in the HPP.
